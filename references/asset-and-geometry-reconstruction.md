# Source asset and geometry reconstruction

Use this workflow for source-sized or pixel-sensitive Figma reproductions. Scope the inventory to the requested frames and states; avoid exporting every node blindly.

1. Resolve the file, frame/node ID, parent, natural viewport and current state. Record per-state copy, selection, scrolling, fixed controls and overlays so comparisons use the right source.
2. Separate editable text, controls and layout from source-backed visual leaves: logos, icons, artwork, photographs and textures. Use SVG for source vectors when appropriate and raster formats for source imagery. Reuse exact project assets when available. Export compound artwork as a parent when it preserves source appearance, or as separate layers when independent motion, clipping or state changes require it; verify the composition either way.
3. Map each meaningful layer to its source node and local asset or live element. Record its position and size in the relevant parent coordinate system, z-order, opacity, rotation/transform origin, clipping/masks, fills, blend modes and effects when visible. Preserve SVG natural dimensions, aspect ratio and viewBox and mount it in the measured slot. Record source text styles and text-box bounds separately.
4. For a fixed, pixel-sensitive artboard, use measured coordinates and absolute positioning where appropriate, especially for layered or animated artwork. Keep text and semantic controls live. Avoid applying fixed coordinates indiscriminately to dynamic lists, forms, variable content or responsive layouts; use flex/grid/flow and constraints where they better preserve the source relationship.
5. Implement each state as a deterministic fixture. Reuse components only if source-specific text, child count, selected state, overlays and dimensions stay faithful. Use source node IDs to keep asset and state mappings traceable.
6. Verify the exact frame at its source viewport with fonts/images loaded and the correct scroll and state. Check slot dimensions, parent transforms, crop, layering, typography, fixed controls and interactive overlays. Recheck after visual fixes, and document unresolved differences.

For existing mixed-layer implementations, trace the target from its visible rendered element through DOM, SVG, iframe, canvas or raster layers to the actual source and state; a matching string in a hidden layer is not proof it controls the display. When replacing outlined SVG text with live text, hide only the corresponding old glyphs and verify the replacement is visible, aligned, selectable and not duplicated in each affected state and language. For raster-baked text, use an appropriate source or reconstruct the affected region; do not cover unrelated content blindly. Preserve animation and event ownership outside the requested change.

Distinguish exported file bounds from the intended visual bounds: shadows, padding, crops or masks may extend beyond the source slot. Measure the content, offsets and overflow in the parent coordinate system and retain the asset's geometry; use a measured wrapper, crop or mask where appropriate, then inspect the final composite rather than redrawing the source to fit mistaken bounds.

Where a separate interaction hit area is necessary, keep the source visual intact and use semantic controls with accessible labels, focus and keyboard operation. Record the visual and hit-area bounds separately, and check that the hot area does not obstruct neighboring controls.

Do not ship an entire frame as a background or image in a live frontend. Ordinary headings, labels and buttons remain DOM text; logos and source artwork with integral lettering are graphical assets. Do not derive motion timing from still states without identifying it as an interpretation. See [font packaging](font-packaging.md) and [visual comparison](visual-comparison.md).
